## 一、弹出菜单体系（模型选择 / Mode 选择 / 通用下拉）

### 1.1 现状问题

| # | 问题 | 位置 | 严重度 |
|---|------|------|--------|
| 1 | **菜单无出入场动画**：Overlay 直接 insert/remove，菜单瞬间出现/消失，感受生硬 | `_CascadeConfigMenu._openMenu()`、`_ModeIconMenu`、`ChipDropdown` | 高 |
| 2 | **级联层级切换无过渡**：provider → model → 思考深度三级切换时内容直接替换，无滑动/渐变方向感，用户失去空间定位 | `_CascadeConfigMenu._levelList()` | 高 |
| 3 | **无背景遮罩（scrim）**：菜单打开后背景完全可透视且无任何暗化，用户注意力无法聚焦到菜单上 | 所有 Overlay 菜单 | 中 |
| 4 | **菜单打开期间滚动不跟随**：位置在打开时一次性计算（`localToGlobal`），若列表滚动或键盘弹出，菜单悬浮在错误位置 | `_openMenu()` 系列 | 中 |
| 5 | **Android 返回键无法关闭 Overlay 菜单**：OverlayEntry 不在路由栈中，按返回直接退出页面而非关闭菜单 | 所有 Overlay 菜单 | 高 |
| 6 | **无键盘/无障碍支持**：菜单项没有 Semantics、不支持焦点导航，TalkBack/VoiceOver 无法正确朗读菜单结构 | 所有 Overlay 菜单 | 中 |
| 7 | **选中反馈仅关闭菜单**：选择模型后菜单立即消失，触发器文字更新无过渡（如 fade），用户不确定是否生效 | `_CascadeConfigMenu` | 低 |
| 8 | **菜单宽度固定 250px**：模型名过长时被 ellipsis 截断，无法看到完整名称做决策 | `_CascadeConfigMenu` width=250 | 低 |

### 1.2 改进方向

1. **入场动画**：菜单从触发点做 `scale(0.95→1.0) + fade(0→1)`，时长 150–200ms，曲线 `easeOut`；退场反向 100–150ms。
2. **级联过渡**：层级切换用 `AnimatedSwitcher` + 水平位移（进入从右向左，返回从左向右），配合标题栏返回箭头，建立"下钻-返回"的空间心智。
3. **轻量 scrim**：背景加 `Colors.black.withOpacity(0.08~0.15)` 渐入，点击 scrim 关闭菜单。
4. **路由化或 ScrollListener**：菜单打开期间监听锚点位移，偏移超阈值自动关闭；或改用 `showMenu`/自定义 `PopupRoute` 获得系统级定位与返回键支持。
5. **返回键处理**：若保留 Overlay 方案，用 `PopScope`/`WillPopScope` 拦截，优先关闭菜单。
6. **无障碍**：菜单容器加 `Semantics(namesRoute: true)`，每个选项为可聚焦按钮。
7. **选中确认**：触发器文字切换时做 150ms `AnimatedSwitcher`（fade），让用户感知"值变了"。

### 1.3 验收标准

- [ ] 菜单出现/消失有可感知的动画，无闪跳
- [ ] 三级下钻有方向感，返回时内容从左侧滑入
- [ ] Android 返回键第一优先级关闭已打开的菜单
- [ ] 菜单打开时背景有轻微暗化

## 二、复制功能的展示逻辑

### 2.1 现状问题

| # | 问题 | 位置 | 严重度 |
|---|------|------|--------|
| 1 | **复制按钮永远可见、无处不在**：每条 AI 文本块右侧、每条用户气泡左侧、每个代码块右上角均有 30px 圆形按钮，造成持续视觉噪音 | `StreamBlockView._copyBtn()`、`MarkdownView._copyBtn()` | 高 |
| 2 | **用户消息也带复制按钮**：用户自己发的话几乎不需要复制，按钮纯属干扰，且位于气泡左侧，视觉上像"另一个气泡" | `StreamBlockView._user()` | 高 |
| 3 | **复制成功无按钮态变化**：点击后仅弹 SnackBar，按钮本身无任何状态反馈（如变勾），快速连续操作时不确定是否点中 | `copyToClipboard()` | 中 |
| 4 | **SnackBar 作为轻量反馈过重**：底部浮动 SnackBar 与输入区/批准卡争夺注意力，且多条快速复制时 SnackBar 排队堆叠 | `copyToClipboard()` | 中 |
| 5 | **流式输出中复制按钮也在**：AI 还在打字时文本不完整，此时复制得到半截内容，按钮不应在流式未完成时出现 | `_textBlock()` | 中 |
| 6 | **触控目标偏小**：30×30 的按钮低于 44pt 最小触控标准，手指粗的用户容易误触相邻区域 | `_copyBtn()` | 低 |

### 2.2 改进方向

1. **渐进披露（Progressive Disclosure）**：
   - AI 文本块：复制按钮默认隐藏（opacity 0），**长按消息区域**时浮现操作条（复制/朗读等）；桌面端 hover 时显示。
   - 代码块：保留右上角复制按钮（代码复制是高频操作），但缩小视觉权重（无边框幽灵按钮，hover/按压时加底色）。
2. **移除用户气泡的复制按钮**：用户自己的消息不需要复制入口；如确需，收入长按菜单。
3. **按钮态变化**：复制成功后图标从 `copy` 变为 `check`，颜色变为 `approve`，持续 1.5s 后恢复。这是**就地反馈**，比 SnackBar 更快被感知。
4. **废弃 SnackBar 用于复制反馈**：就地 icon morph 已足够；如需文字确认，用按钮旁的微型 tooltip（"已复制"，1s 淡出）。
5. **流式完成才出现**：`BlockKind.text` 在该 block 仍在追加时（busy 且为末块）不渲染复制按钮，流完后 fade in。
6. **触控目标 ≥ 44pt**：视觉尺寸可保持 30px，但用 `SizedBox`/`Padding` 扩展命中区域到 44×44。

### 2.3 验收标准

- [ ] 正常浏览时消息区无持续可见的复制按钮（代码块除外）
- [ ] 复制成功后按钮就地变勾 ≥ 1s
- [ ] 流式输出中不出现复制按钮
- [ ] 所有可点击元素命中区域 ≥ 44×44pt

## 三、生成状态动效（AI 正在输出）

### 3.1 现状问题

| # | 问题 | 位置 | 严重度 |
|---|------|------|--------|
| 1 | **无任何"正在生成"视觉指示**：AI 输出中，消息区唯一变化是文字在增长——若用户在看别处或内容增长慢（思考阶段），完全感知不到"它在工作" | 全局 | **极高** |
| 2 | **等待首个 chunk 期间完全空白**：发送消息后到第一个 token 到达之间（可能 2–10s），界面零反馈，用户以为发送失败 | `_send()` 后 | **极高** |
| 3 | **思考块无进行中动效**：`_think()` 折叠态只显示静态的"思考"二字，AI 正在思考时与思考完毕的视觉完全相同 | `StreamBlockView._think()` | 高 |
| 4 | **停止按钮是唯一状态信号**：红色停止按钮仅 32px，位于输入栏右侧角落，作为"AI 正在工作"的唯一指示器过于隐蔽 | `_InputBar` running 态 | 高 |
| 5 | **流式文本无光标/尾部指示**：文字追加时末尾无闪烁光标或渐隐尾巴，阅读体验像"文字突然蹦出来" | `_textBlock()` | 中 |
| 6 | **工具执行中动画过于简陋**：仅一个 12px 的 `CircularProgressIndicator`，无耗时计数、无进度语义 | `_tool()` running 态 | 低 |

### 3.2 改进方向

1. **等待首 token 阶段 — 思考呼吸动画**：
   - 发送后立即在消息流末尾插入"AI 头像/标识 + 三点呼吸（·  ·  ·）"或 Kimi 风格的光斑呼吸动画。
   - 动画节奏：1.2–1.8s 周期，透明度 0.3↔1.0 或缩放 0.8↔1.0，传达"活着、在想"。
   - 第一个 chunk 到达时，动画块平滑过渡（fade out + 内容 fade in）为实际内容。
2. **思考块进行中状态**：
   - 折叠态标题从静态"思考"变为"思考中…" + 微型 shimmer 或旋转图标；
   - 展开态文字末尾追加闪烁光标（`▍`，opacity 周期 0.8s）；
   - 思考完成后标题回落为"思考 · 3.2s"（附耗时），图标静止。
3. **流式文本尾部光标**：正在追加的 text block 末尾渲染一个 2px 宽、行高 1.2em 的竖线光标，accent 色，闪烁周期 0.8–1s；流完成后光标 fade out。
4. **全局生成状态条（可选增强）**：顶栏状态点或输入栏上方增加一条 2px 的 indeterminate 进度条（accent 色往复扫描），busy 全程可见，完成后收起。
5. **工具执行**：running 态附 elapsed 计时（"执行中 · 4s"），超 10s 后计时变 warning 色提示耗时。
6. **停止按钮增强**：busy 时停止按钮做轻微 pulse（scale 1.0↔1.06，2s 周期），提升存在感。

### 3.3 验收标准

- [ ] 发送后 ≤ 300ms 内出现等待动画
- [ ] AI 输出全程，消息区有可感知的"正在生成"动态元素
- [ ] 思考中 vs 思考完成有明确视觉区分
- [ ] 生成结束后所有过程态动画干净退场，不留残余

## 四、消息列表与滚动体验

### 4.1 现状问题

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **新消息无入场动画**：block 直接出现在列表中，尤其用户发送的气泡"弹"出来没有过渡 | 中 |
| 2 | **上滑后无"回到底部"浮动按钮**：用户翻看历史时新消息持续到来，没有快捷方式回到最新位置，只能手动滚到底 | 高 |
| 3 | **上滑时缺少新消息提示**：不在底部时收到新消息，用户完全无感知（无 badge、无提示条） | 中 |
| 4 | **会话切换内容瞬间替换**：切换 session tab 后消息列表无过渡地整体换掉，方向感丢失 | 中 |
| 5 | **历史会话加载无 skeleton**：`open_history` 回放需要网络往返，期间消息区空白无加载态 | 中 |
| 6 | **dock 高度测量导致列表跳动**：`_measureDock()` 在高度变化时 setState 修改 padding，可能引起可见的布局跳变 | 低 |

### 4.2 改进方向

1. **消息入场**：新 block 以 `fade + translateY(8→0)` 入场，150ms easeOut；仅对新增项生效（用 key 区分），已有项不重播。
2. **回到底部 FAB**：当 `_atBottom == false` 时，在 dock 上方右侧浮现圆形按钮（↓ 箭头），点击平滑滚到底；若期间有新消息，按钮上附小圆点或"N 条新消息"标签。
3. **新消息 toast 条**：不在底部时收到新消息，在 dock 上方显示悬浮条"↓ 新回复"，点击跳转；3s 无操作自动消失。
4. **会话切换过渡**：列表内容用 `AnimatedSwitcher`（fade 150ms）或方向性滑动切换。
5. **加载骨架屏**：打开历史会话到 blocks 到达之间，显示 3–4 行 shimmer 骨架条。
6. **dock 高度**：用 `AnimatedPadding`/`AnimatedContainer` 过渡 padding 变化，避免跳变。

### 4.3 验收标准

- [ ] 上滑后出现回到底部按钮，点击 ≤ 300ms 内到达底部
- [ ] 不在底部时的新消息有明确提示机制
- [ ] 打开历史会话时不出现无反馈的空白期

## 五、输入区体验

### 5.1 现状问题

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **发送/停止按钮切换无过渡**：两个 32px 圆形按钮直接替换，颜色和图标同时突变 | 中 |
| 2 | **busy 时输入框仍可输入但发送无效**：`_send()` 中 busy 直接 return 无任何提示，用户打完字点发送没反应，以为出了 bug | 高 |
| 3 | **快捷短语（chips）硬编码且常驻**：三个固定短语永远占据 dock 上方 34px，与当前上下文无关，浪费纵向空间 | 中 |
| 4 | **附件按钮点击只弹"即将支持"**：功能不可用但按钮可见可点，违反"可见即可用"原则 | 中 |
| 5 | **输入框禁用态提示不足**：离线时仅 hint 变为"先连接中继"，输入框外观无变化（仍白底），可点但不可输入 | 低 |
| 6 | **Slash 面板无动画**：命令面板出现/消失无过渡，且选中后面板消失也是瞬间 | 低 |

### 5.2 改进方向

1. **按钮 morph 动画**：发送↔停止用 `AnimatedSwitcher`（scale + fade），或 `AnimatedContainer` 做颜色渐变 + `AnimatedSwitcher` 做图标切换，时长 200ms。
2. **busy 时输入反馈**：
   - 方案 A（推荐）：busy 时输入框保持可输入（允许排队下一条指令），发送按钮变为"排队"语义或禁用+tooltip "等 Kimi 说完";
   - 方案 B：busy 时输入框底部出现 1px 进度线，发送时轻微 shake + 提示"Kimi 正在输出，完成后自动发送/请等待"。
3. **chips 上下文感知**：空闲时才显示 chips；busy 时收起（释放空间给停止反馈）；未来可基于会话上下文动态推荐。
4. **不可用功能隐藏或降级**：附件按钮在 v1 直接隐藏，或改为灰色禁用态 + 点击无响应（而非弹 toast 告知"即将支持"）。
5. **禁用态视觉**：离线时输入框底色变为 `background` 色（灰），与可用态形成明确对比。
6. **Slash 面板动画**：出现用 `AnimatedSize` + fade（从输入框上方展开），消失反向。

### 5.3 验收标准

- [ ] busy 时用户操作发送有明确的反馈（文字提示或视觉拒绝），无"静默吞掉"
- [ ] 发送/停止切换有可感知的过渡动画
- [ ] 界面上不存在"点了只弹即将支持"的按钮

## 六、批准卡（Permission Sheet）

### 6.1 现状问题

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **批准卡出现无入场动画**：从 dock 上方直接弹出，作为最高优先级的交互元素，缺少"请注意"的动态入场 | 中 |
| 2 | **倒计时仅文字，无进度可视化**：`mm:ss` 数字不够直觉，剩余时间的紧迫感无法一眼感知 | 中 |
| 3 | **超时后卡片行为不明确**：倒计时归零后仅显示"已超时"文字，卡片仍停留，按钮仍可点，用户不知道该做什么 | 中 |
| 4 | **多选项按钮无权重区分**：批准（绿）/ 本会话（灰）/ 拒绝（红底）三等分排列，最常用操作没有视觉优先级 | 低 |

### 6.2 改进方向

1. **入场**：从底部 `translateY(24→0) + fade`，200ms easeOut；配合轻微 haptic（iOS: `.warning`）。
2. **进度环**：倒计时 chip 内加 3px 环形进度（顺时针消减），颜色随剩余时间 green→orange→red 渐变。
3. **超时态**：超时后按钮组灰化禁用，卡片加"已超时 · Kimi 已按默认策略处理"说明，5s 后自动收起（若中继已 invalidate）。
4. **主操作突出**：批准按钮占更大宽度比（如 2:1:1），或置于最右（移动端拇指热区）。

### 6.3 验收标准

- [ ] 批准卡入场有动画 + 触觉反馈
- [ ] 倒计时一眼可判断紧迫程度（颜色 + 进度可视化）
- [ ] 超时后界面状态明确，不留下可操作但无效的按钮

## 七、连接状态与错误处理

### 7.1 现状问题

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **横幅出现/消失无过渡**：连接恢复后横幅瞬间消失，断开时瞬间出现 | 低 |
| 2 | **顶栏 9px 状态点语义不明**：绿/黄/灰小圆点无文字辅助，新用户无法理解含义 | 中 |
| 3 | **`relay.error` 仅存储不展示**：`lastError` 写入后没有任何 UI 消费它，错误被吞掉 | 高 |
| 4 | **重连无进度/次数感知**：退避重连时用户只看到"重连中…"，不知道第几次、下次间隔多久 | 低 |

### 7.2 改进方向

1. **横幅动画**：用 `AnimatedSize`/`AnimatedCrossFade` 展开收起，200ms。
2. **状态点可点**：点击状态点弹出 popover 说明当前状态（"中继在线 · Kimi 正常"），或长按显示详情。
3. **错误可见**：`relay.error` 触发时，以非阻断 toast/横幅展示错误摘要，可点击查看详情或重试。
4. **重连细节**：横幅附"第 N 次 · 下次 Xs 后"（中继已有退避逻辑，前端透出即可）。

### 7.3 验收标准

- [ ] 中继报错时用户能在界面上看到错误信息
- [ ] 连接状态变化有平滑过渡，无闪跳

## 八、微交互与触觉反馈

### 8.1 现状问题

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **Pressable 仅透明度反馈**：所有按钮按压只有 opacity 0.55 变化，无 scale、无 haptic，手感"纸片化" | 中 |
| 2 | **全局无触觉反馈**：发送消息、批准/拒绝、切换会话、复制成功等关键操作零 haptic | 中 |
| 3 | **折叠/展开无弹性**：think/tool 块的 `AnimatedSize` 是线性的尺寸过渡，缺少物理感 | 低 |

### 8.2 改进方向

1. **按压反馈升级**：`Pressable` 改为 `opacity 0.7 + scale 0.96`，恢复时带轻微回弹（curve: easeOutBack 弱版本）。
2. **关键操作 haptic**（iOS HapticFeedback / Android Vibrator）：
   - 发送消息：`.light`
   - 批准/拒绝：`.medium` / `.heavy`
   - 复制成功：`.selection`
   - 批准卡出现：`.warning`
3. **折叠弹性**：curve 改为 `Curves.easeOutCubic`，时长 250ms。

## 九、信息密度与视觉层级

### 9.1 现状问题

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **顶栏元素拥挤**：汉堡菜单 + 模型胶囊 + 状态点 + mode 按钮挤在一行，模型名长时胶囊被压缩到难以辨认 | 中 |
| 2 | **会话 tab 标题最大宽度仅 110px**：中文约 7 个字即截断，多数会话标题无法完整显示 | 中 |
| 3 | **工具块默认折叠隐藏关键信息**：running 态默认折叠，用户必须手动展开才能看到正在执行什么命令 | 中 |
| 4 | **思考块折叠态无摘要**：只显示"思考"二字，不展示思考内容的前 N 字预览 | 低 |

### 9.2 改进方向

1. **顶栏呼吸空间**：模型胶囊限制最大宽度（如屏幕 55%），超长时显示短名（provider 缩写 + 模型核心名）。
2. **tab 宽度自适应**：maxWidth 提升到 160px，或按屏幕宽度动态计算（`screenW * 0.4`）。
3. **running 工具块自动展开**：`tool_call` 到达且 status 为 running 时默认 `_open = true`，完成后可自动折叠回摘要态。
4. **思考摘要**：折叠态显示首行前 40 字作为灰色预览文本。

## 十、可访问性与基础体验

### 10.1 问题清单

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | 会话 tab 关闭按钮 18×18px，远低于 44pt 触控标准 | 高 |
| 2 | 消息正文 `Text` 不可选中（仅代码块 `SelectableText`），长文本无法局部复制 | 中 |
| 3 | 无暗色主题（设计稿已登记"月之暗面"为可选变体，但代码仅 `AppTheme.light()`） | 中 |
| 4 | 全部色彩为硬编码 const，无 `ColorScheme`/`ThemeData` 语义化，暗色适配需全量改动 | 中 |
| 5 | 无 Dynamic Type 支持：字号全部硬编码，系统大字号设置不生效 | 低 |
| 6 | Overlay 菜单内文字对比度：`placeholder` 色（#C0C0C0）在白底上对比度仅 1.6:1，低于 WCAG AA 的 4.5:1 | 中 |

### 10.2 改进方向

1. 所有交互元素命中区域 ≥ 44×44pt（视觉可小于，命中不可小于）。
2. AI 回复正文改用 `SelectableText.rich` 或长按启用选择。
3. 色彩令牌迁移到 `ThemeExtension` 或 `ColorScheme`，为暗色主题铺路。
4. 文字尺寸用 `TextScaler` 感知系统设置，或至少提供应用内字号调节。
5. 装饰性低对比度元素确保不承担信息传达功能。

## 优先级排序（推荐实施顺序）

| 优先级 | 改进项 | 理由 |
|--------|--------|------|
| P0 | 生成状态动效（第三章） | AI 产品最核心的状态感知，缺失 = 用户以为坏了 |
| P0 | busy 时发送无反馈（§5.1-2） | 静默吞操作 = 用户信任崩塌 |
| P1 | 复制按钮渐进披露（第二章） | 每条消息都有的持续视觉噪音 |
| P1 | 回到底部 FAB + 新消息提示（§4.2-2/3） | 长对话核心导航能力缺失 |
| P1 | 菜单出入场动画 + 返回键（§1.2-1/5） | 基础交互品质 |
| P2 | 批准卡入场/进度环（第六章） | 核心功能体验打磨 |
| P2 | 触控目标合规（§10.1-1） | 基础可用性 |
| P2 | 错误可见化（§7.2-3） | 诚实原则的落地 |
| P3 | Haptic / 微交互（第八章） | 手感品质 |
| P3 | 暗色主题基础（§10.2-3） | 架构铺垫 |

## 附录：通用动效参数规范

为保持全应用动效语言一致，约定以下参数：

| 场景 | 时长 | 曲线 | 备注 |
|------|------|------|------|
| 按钮按压恢复 | 120ms | easeOut | — |

| 弹出菜单退场 | 120ms | easeIn | 反向 |
| 面板/卡片入场 | 200ms | easeOut | translateY 16~24→0 + fade |

| 折叠/展开 | 250ms | easeOutCubic | AnimatedSize |
| 流式光标闪烁 | 800ms 周期 | linear | opacity 0↔1 |
| 呼吸/等待动画 | 1400ms 周期 | easeInOut | 三点交错 200ms |
| 状态色变（成功/失败） | 150ms | easeOut | — |
| 回到底部滚动 | 300ms | easeOut | — |
